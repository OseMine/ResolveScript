# Consolidation (`resolvescript build` / `consolidate`)

The **consolidator** merges a multi-file Python package into a **single importable `.py` file** that DaVinci Resolve can execute directly.

## How It Works

```
my_package/
├── __init__.py
├── core.py
├── utils.py
└── menu.py
        │
        ▼
┌───────────────────┐
│  resolvescript    │
│  build            │
└───────────────────┘
        │
        ▼
dist/my_package.py   # Single file, all internal imports resolved
```

## Process

1. **Collect** all `.py` files under package root (respects `exclude` patterns)
2. **Extract** imports → build dependency graph
3. **Order** modules so dependencies come first (cycles fall back to sorted)
4. **Rewrite** internal imports:
   - `from . import core` → commented + `core = _rs_shared` hoisted
   - `from my_pkg import utils` → commented (members already in namespace)
   - `import os` → hoisted to top (stdlib)
5. **Emit** single file with:
   - Module docstring
   - `__future__` imports
   - Stdlib imports
   - Namespace bindings (`_rs_shared = sys.modules[__name__]`)
   - Module bodies in dependency order

## Manifest Configuration

```json
{
  "name": "My Script",
  "package_dir": "my_script",
  "consolidate": {
    "enabled": true,
    "output": "my_script.py",
    "entry": "my_script:main",
    "exclude": ["tests/**", "*_test.py"],
    "no_comment": ["my_script.core"]
  }
}
```

| Field | Description |
|-------|-------------|
| `enabled` | Master switch |
| `output` | Output filename (default: `<name>.py`) |
| `entry` | Dotted entry module (for dependency ordering) |
| `exclude` | Glob patterns to skip |
| `no_comment` | Modules whose internal imports are preserved |

## CLI

```bash
# From project root (uses manifest)
resolvescript build
resolvescript build --output ./releases/my_script.py

# Ad-hoc (no manifest needed)
resolvescript consolidate ./my_package --output ./my_package.py
```

## Output Structure

```python
"""my_script - Consolidated single-file module for DaVinci Resolve.

This file is auto-generated by 'resolvescript build'/'consolidate'.
Do not edit directly - edit the source modules under my_script instead.
"""

from __future__ import annotations

# ruff: noqa: E402,F401,F403,F405
# flake8: noqa: E402,F401,F403,F405

import sys as _rs_sys
_rs_shared = _rs_sys.modules[__name__]
core = _rs_shared
utils = _rs_shared

# Standard library imports
import os
import json

# ==== Module: my_script ====
__version__ = "1.0.0"

# ==== Module: my_script.core ====
def process(data):
    return utils.helper(data)

# ==== Module: my_script.utils ====
def helper(x):
    return x * 2
```

## Rules & Constraints

| Rule | Reason |
|------|--------|
| No `if __name__ == "__main__"` blocks | Consolidated file must be importable |
| Internal imports become namespace bindings | Flat namespace needs `core.attr` to work |
| Stdlib imports hoisted to top | Clean, predictable |
| Cycle detection | Emits sorted order, warns in summary |

## `no_comment` Escape Hatch

Modules listed in `no_comment` keep their internal imports **as-is**. Use for:
- Modules that import optional deps at runtime
- Modules with complex import logic
- Entry points that must stay executable

```json
"no_comment": ["my_script.core", "my_script.cli"]
```

## Exclude Patterns

```json
"exclude": [
    "tests/**",
    "*_test.py",
    "benchmarks/**",
    "*.pyc"
]
```

## Entry Point

The `entry` field tells the consolidator which module is the "root" for dependency ordering:

```json
"entry": "my_script.menu"  # or "my_script:main" for module:function
```

If omitted, the first module in dependency order is used.

## Ad-hoc Consolidation

```bash
# No manifest, no project structure needed
resolvescript consolidate ./any_package --output ./single_file.py
```

Useful for:
- Legacy scripts
- Quick packaging
- CI pipelines without manifest

## Lua Installer

## Verification

The consolidated output is **syntax-checked** before writing:

```bash
# If syntax error:
Consolidated output failed syntax check: unexpected EOF while parsing
```

## Common Issues

| Issue | Fix |
|-------|-----|
| `ImportError` after install | Check `no_comment` for modules with optional deps |
| Missing stdlib import | Add to `no_comment` or check import is actually stdlib |
| Cycle warning | Refactor circular deps, or accept sorted fallback |
| `E402` (module import not at top) | Expected — ruff noqa suppresses |

## Tips

- **Test before consolidating**: `resolvescript dev` / `resolvescript test`
- **Keep source modular**: Consolidation is a build artifact
- **Use `no_comment` sparingly**: Only for genuine dynamic imports
- **Version the output**: Include version in manifest, output filename
